# 会话整理

分类由当前模型在原正常回复中一次填参；脚本只执行和验证，不按关键词、标题或目录名猜归属。

1. `<pi_projects>` 已给出项目名称、对话数、绝对路径和当前会话；仅需整理时附上候选主对话及 `planSchema`，不另查文件或追加模型轮次。侧栏「最近任务」是最近1小时及运行中会话的视图，磁盘仍按月份存放。
2. 项目不超过8个、每项5–10个未归档主对话；不设隐藏项目，项目名最多7字，子会话随主对话。模型在同一份参数中指定合并、移动和拆分；脚本先预演连同当前会话的最终数量，再执行并校验。目标项目已有10个主对话时，脚本按最后助手回复时间归档最早一条，再归入新对话；归档保留历史、ID和子会话，运行中则等待，不删除。总量不足5时当前对话暂留收件目录。
3. 会话物理位置为 `项目根/项目名/YYYY-MM/会话.jsonl`，按建档月份最多三级；每日5点按月归档，运行中会话不移动。保留正文、ID、图片、归档状态及关联子会话，不删除工作资料。
4. 未归属首轮末尾附 `<归属 项目="项目名">对话名</归属>`。仅 `requiresPlan=true` 时，在归属前同次附 `<项目整理>JSON参数</项目整理>`；结束钩子保存参数并只调用一次脚本，自动带 `--plan-file`，不再调用分类模型或其他工具。
5. 整理参数：`renames:[{from,to}]` 改名；`merges:[{from:[来源名],project:已有目标名}]` 明确合并目标；`moves:[{project,ids:[主对话ID]}]` 分类；`splits:[{from,project,ids:[主对话ID]}]` 拆分指定来源。名称及ID全部由模型指定，包含未归属候选；无须整理时传 `{}`。无参数时脚本只能清理真正空登记、计数及校验，不能猜测补齐。标题含「分表」「索引」不代表某个数据库引擎，依据实际对话内容填写。
6. `move/create/merge`、`balance --plan-file 参数文件`、`list`、`verify --session ID` 共用 `pi-project.mjs`；`--defer` 等回复结束，`--preserve-cwd` 保留执行目录。结果在 `project-routing-results/会话ID.json` 和 `project-balance-result.json`；成功即结束，仅报错介入。

正常归属只填项目名和对话名。最后的 `--verify` 已在同一次调用内验证，不再单独运行验证工具：

```sh
node tools/pi-project.mjs move --project "Pi工作台" --title "整理项目与对话" --verify
```
