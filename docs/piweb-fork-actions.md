# 对话框的复制 / 分叉 / 固定（与 Claude 桌面端对齐）

2026-11-17。每个已完成的回答下方、模型/时间行的左侧是三个按钮，顺序和位置与 Claude 桌面端一致：**复制 · 从此处分叉 · 固定为章节**。常显（暗色），悬停加深。

## 分叉（和桌面端一样）

| 入口 | 新会话里有什么 | 原会话 |
|---|---|---|
| 回答下方的分叉按钮 | 到这一轮结束为止的全部内容 | 原样不动，运行中也能分叉 |
| 用户消息下方的分叉按钮 | 这条消息**之前**的全部内容；这条消息的原文（含图片）放进新会话的输入框，不自动发送 | 同上 |
| 输入 `/fork` | 当前会话到现在的全部内容，并打开它 | 同上 |
| 输入 `/fork <提示词>`，或在输入框按 `Ctrl+Alt+Enter`（桌面端的「在分叉会话中发送」） | 同上，提示词在新会话里直接开始运行，**留在当前会话**；快捷键发送的是输入框里的文字，分叉失败时文字留在输入框；手机端 `Ctrl+Alt+Enter` 仍是原来的「追加」 | 同上 |

- 新会话标题：`<原标题> (fork)`，从分叉再分叉依次 `(fork 2)`、`(fork 3)`。原标题取第一行、最多 40 字，保证后缀在窄侧栏里看得见；没有标题的会话不起名（侧栏仍显示首条消息）。
- 新会话顶部一行「分叉自 <原会话>」，点击回到原会话；原会话在分叉所在的那一轮下面显示「已在此分叉 <标题>」，同一处分叉多次显示「此处已分叉 N 次」加各个链接。
- 分叉点：新会话复制到该处为止的条目，条目 id 原样保留；标记靠比较两边的条目 id 找到分叉点（`GET /api/sessions/<id>/forks`），所以也覆盖过去用 Pi 命令行或旧按钮做的分叉。
- 服务端：`fork_branch` 命令多了 `before`（不含该条目，用于用户消息）和 `name`（给新会话起名），并且不再因为会话在运行而拒绝（它只读已保存的文件，不碰运行中的会话）。原来的 `fork`（会替换并关闭源会话）不再被界面使用，保留给命令行式调用。
- 不做的：桌面端的「每个分叉开独立 worktree」（pi-web 没有这个概念）、远程会话分叉、侧栏会话右键菜单里的「分叉会话」（用 `/fork`）、消息右键菜单。

## 固定为章节

回答下方的图钉按钮把这一轮固定下来，右上角「问答导航」里被固定的回答带图钉，列表头部多一个图钉开关，打开后只看已固定的。固定记录存在浏览器本地（`localStorage` 的 `pi-web:pins:<会话 id>`），按会话、按回答条目保存，不进会话文件，也不随分叉复制。
